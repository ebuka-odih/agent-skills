# Spec interview

Three rounds. Ask a round, wait, write down answers, then the next round. Propose an answer for every question.

## Round 1 — problem and people
1. What problem does this solve, and for whom? (one sentence each)
2. Who are the user types (roles)? e.g. *studio owner, instructor, member, admin*
3. How do they solve it today, and what's painful about that?
4. What does success look like in 3 months? (a number if possible: users, bookings, revenue, time saved)

## Round 2 — what it does
5. Walk me through the 3–5 most important journeys, step by step, per user type.
   Propose them yourself from round 1: "Member finds a class → books → pays → gets reminder → attends."
6. For each journey: what must happen for it to count as working? (becomes `accept:` lines)
7. What's explicitly **not** in the first release? (propose 3–5 tempting extras)

## Round 3 — limits
8. Constraints: deadline, budget, platforms (web/iOS/Android), languages, accessibility, compliance (GDPR, HIPAA, PCI)
9. Integrations that must exist: payments, email, calendars, existing systems
10. Non-functional needs that users would notice: speed, uptime, offline, data export
11. What would make you consider the project a failure?

## Rules
- Batch questions; never one at a time.
- Turn vague answers into a proposed concrete one and ask "right?" ("fast" → "pages load in < 2 s on 4G — right?").
- Anything still unknown after round 3 → Open questions table with an owner.
- Stop at 3 rounds. Remaining gaps are Open questions, not round 4.
